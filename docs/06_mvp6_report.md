# 6차 MVP — 롤링 페어 재발굴 보고서

> 5차 MVP까지의 결론: "정적·동적·앙상블 모두 같은 페어 풀에서 베타만 다름."
> **6차 MVP가 답한다: 페어 풀 자체가 매월 절반씩 바뀐다.**

## 1. 문제 정의

1~5차 MVP의 한계 — 모든 분석이 한 가지 가정 위에 서 있었다.

> "한 번 발굴된 페어는 시간이 지나도 유효하다."

이 가정이 맞는지 단 한 번도 검증한 적 없었다. 6차 MVP는 **이 가정을 직접 부순다**.

## 2. 방법

비유로 풀면:
- 정기 건강검진. 매월 페어 풀 전체를 재검정.
- 죽은 페어(공적분 깨진) → 폐기
- 새로 형성된 페어 → 영입
- 살아남은 페어 → 베타·half-life 갱신

```python
class RollingPairsManager:
    def __init__(self, finder, lookback_days=365, refresh_every_days=30):
        # 매 30일마다 최근 1년치 데이터로 페어 재발굴
```

설정:
- **Lookback**: 365일 (1년치로 페어 검정)
- **Refresh**: 30일 (매월 재검정)
- 데이터: 3년치 (753일) → 13번 검정 가능

## 3. 충격적 결과 ①: 영구 견고 페어 = 0개

| 항목 | 값 |
|---|---|
| 검정 횟수 | 13회 |
| 적어도 한 번 적격 | **58개 페어** |
| **항상 적격 (모든 13회)** | **0개** |
| 한 번만 적격 (flash) | 32개 |

**378개 페어 중 단 하나도 1년 내내 안정적이지 않다.**

가장 오래 산 페어조차 BAC~NVDA의 **300일 / 1100일 = 27.4%**만 적격.

## 4. 충격적 결과 ②: 회전율 50% / 30일

매월 평균:
- **4.6개 신규 영입**
- **4.7개 폐기**

전체 풀 크기 평균 8.8개인데 이 중 절반 가까이가 매월 교체된다.

**시사점**: "한 번 잡은 페어로 1년 운용"은 불가능. 페어 트레이딩의 본질이 "지속적 교체 작업"이라는 것.

## 5. 충격적 결과 ③: 1차 MVP의 진실

1차 MVP가 단일 70/30 split으로 발굴한 7개 페어를 6차 MVP가 13개월 동안 추적한 결과:

| 페어 | 적격 일수 | 평가 |
|---|---|---|
| **BAC~NVDA** | **300일** | ✓ 진짜 견고 (3차 Grade A 확증) |
| **GDXJ~GLD** | **120일** | ✓ 안정 (펀더멘털 합리적) |
| MA~T | 60일 | △ 불안정 |
| **GDX~KO** | **30일** | △ 단 1회만 (1차 MVP의 우연) |
| NVDA~VZ | 0일 | ✗ 한 번도 적격 안 됨 |
| MA~WFC | 0일 | ✗ 한 번도 적격 안 됨 |
| JPM~SLV | 0일 | ✗ 한 번도 적격 안 됨 |

**1차 MVP가 발굴한 7개 중 3개는 6차에서 한 번도 적격 안 됨**. 단일 시점 통계 검정의 거짓 양성.

## 6. GDX~KO의 진짜 답

세 단계에 걸친 진단의 변천사:

| MVP | 진단 |
|---|---|
| 1차 | "Sharpe -0.49, 망함" (단일 split) |
| 2차 | "Sharpe +2.24, 견고" (K-fold) |
| 3차 | "Grade A, 모든 진단 통과" (오버핏 진단) |
| **6차** | **"13번 중 1번만 적격, 사실상 페어 아님"** |

3차까지의 모든 "견고" 판정은 365일 lookback에서 한순간 잡힌 페어를 평가한 결과. **6차가 보여준 진실은 그 한순간이 전부였다는 것**.

이게 명세서 v2가 §2 실전 함정에 적은 "OOS 공적분 붕괴 빈번 → 롤링 윈도우 재검정 필수"의 가장 강력한 실증.

- LUV~MA: 120일

- **§4 펀더멘털 필터의 다음 우선순위 후보**: "한 자산이 너무 많은 페어를 형성하면 거짓 양성 의심"

## 9. 1~6차 MVP를 관통하는 메타 교훈

각 MVP가 답한 질문:

| MVP | 질문 | 답 |
|---|---|---|
| 1차 | 페어 트레이딩이 작동하는가? | "GDX~KO 망함" (잘못된 결론) |
| 2차 | 단일 split이 신뢰할 만한가? | "아니다, 5-fold 필요" |
| 3차 | 통계가 진짜 신호인가? | "Sensitivity + Permutation로 확인" |
| 4차 | 베타가 변하는 페어는? | "Kalman은 regime change 보험" |
| 5차 | 두 베타를 합치면? | "안정성↑ 수익↓" |
| **6차** | **페어 자체는 영구한가?** | **"아니다. 매월 50% 회전한다"** |

**6차의 답이 가장 본질적**. 1~5차의 모든 정교한 분석이 "어떤 페어를 발굴할 것인가"에 집중한 반면, 6차는 "그 페어가 얼마나 오래 살아남는가"를 측정.

> **결론**: 페어 트레이딩의 본질은 한 페어를 잘 운용하는 게 아니라, **죽어가는 페어를 빠르게 폐기하고 새 페어를 빠르게 영입하는 시스템**을 만드는 것.

## 10. 통합 권장 — 실전 페어 트레이딩 시스템

이제 1~6차의 모든 발견을 통합한 production-grade 시스템 설계:

```
매월 1일 (Refresh Day):
  1. 최근 365일 데이터로 페어 후보 발굴 (§1 ADF + §2 공적분)
  2. 각 후보에 대해 3단 검증 (K-fold + Sensitivity + Permutation)
  3. Grade A/B 페어만 운용 풀에 포함
  4. 이전 풀과 비교 → 폐기/유지/신규 결정
  5. 살아남은 페어의 베타·half-life 갱신
  6. 포트폴리오 켈리로 자본 배분

매일:
  7. 각 페어의 Z-score 계산
  8. 진입/청산 신호 실행
  9. force_close 모니터링 (Z 발산 시 즉시 손절)
```

이게 1~6차 MVP의 종합 결론. 단일 발굴/단일 베타가 아닌, **지속적 갱신 시스템**.

## 11. 추가 작업 후보 (낮은 우선순위)

- **§4 펀더멘털 필터**: LUV의 다중 페어 형성 의심 해결
- **§7 Kalman 동적 베타**: 살아남은 페어 내부의 정교한 베타 조정
- **§4-C 포트폴리오 켈리**: 다중 페어 동시 운용 시 자본 배분

이런 것들은 6차의 롤링 인프라 위에서 의미가 있음. 인프라 없이 적용하면 다 죽은 페어에 정교한 작업하는 격.
